# tests/ 账务类测试逐个甄别（2026-11-21）

- 范围：`tests/` 下 71 个 `test_*.py` + 2 个辅助模块（`style_bible_consumption.py`、`tautology_criterion.py`，无独立用例，不计入用例数）。
- 方法：逐文件读 docstring 与全部断言（依据 `out/工具/_digest.txt`、`_compact.txt`、`_scan.json`），并抽查源码确认断言方式（是否真渲染/真调用，还是只读仓库文本）。
- 分类标准：
  - **A = 渲染画面 / 管线行为**：以 numpy/PIL 帧分析、`renderToStaticMarkup`、node 子进程真实渲染、管线函数调用为断言对象 —— 建议保留。
  - **B = 仓库账本**：路径形状、哈希钉、`git ls-files` 引用解析、清单新鲜度、文件计数、注释/文档与仓库文本比对 —— 可裁候选。
  - **C = 契约与 schema**：zod/JSON Schema/Python-TS 镜像一致性、字段读写链路 —— 建议保留。
- 判定结论先行：**此前「产出类约 26 个在钉仓库文本」的估计偏高**。逐个读过断言后，多数被点名的文件实际用渲染产物或真实调用取证据（文件里有 `numpy`/`PIL`/`renderToStaticMarkup`/`node` 子进程），不属于账本类。真正的纯账本测试只有 **4 个文件 / 9 个用例**；另有 5 个文件**夹带账本断言**，裁账务部分需要拆文件。

## 统计

- 现状：**71 个测试文件 / 691 个 pytest 用例**（另有 2 个辅助模块、1 个 `.mjs` 探针、无 conftest）。
- 方案一（只裁纯账本）：删 4 个文件 → 剩 **67 个文件 / 682 用例**（-9）。
- 方案二（裁纯账本 + 拆混写文件的账本用例）：删 4 个文件 + 拆出约 13~15 例 → 剩 67 个文件 / **约 667~669 用例**。
- 保留侧主力是 C 类契约（schema/镜像/对齐，约 150 例）与 A 类渲染行为（约 520 例）；账本类占比不足 4%。
- 与旧口径的差异：`_classify.txt` 曾把约 26 个产出文件记为“钉仓库文本”；逐个核验后其中 21 个实为渲染/调用型测试（docstring 里“provenance comment”多在解释为何**不用**文本断言），本清单已纠正。
