## 〇、先说一条把工单的前提推翻的实测

工单第二节写：

> `c10_bar_long` 的 `chart.emphasisIndex = 6` —— **实测 t=4.2s 那一帧跳变就是它**
> ⇒ 砍到 150 帧会把它砍掉。

**这条不成立。** 无损渲染下不存在这次跳变：

| 帧（绝对） | 1598→1599 | 1599→1600 | 1600→1601 | **1601→1602** | 1602→1603 | 1603→1604 |
|---|---|---|---|---|---|---|
| 无损 `still.mjs` | 0 | 0 | 0 | **0** | 0 | 0 |
| 成品 mp4（有损） | — | 96449 | 2655 | **5** | 5 | 963 |

t=4.2s = 绝对帧 1602。**无损下前后完全逐像素相同**，成品 mp4 上的"5 px"是编码抖动
——同一段 mp4 上两个同样静止的帧之间就有 2655 px 的差。**那次"跳变"是编码噪声，
不是画面事件。**

原因在渲染源码里。`emphasis` 不是一次闪现，是一条**上升后保持**的曲线
（`charts/lifecycle.ts`）：

| | 600 帧（现状） | 150 帧（改后） |
|---|---|---|
| `emphasis` 到达 1.0 的帧 | f133（t=2.217s） | f69（t=1.150s） |
| 之后 | 保持 1.0 | 保持 1.0 |

`lifecycle.ts` 自己的注释就是这么写的："A premium chart says one thing by doing
nothing to it." 所以"砍到 150 会砍掉强调"这个前提，来自把**保持**读成了**闪现**。

## 一、B-3：c10 的长静止

### 判据：静止段是不是缺陷，取决于场景有没有内容兑现它的时长

实测（600 帧图，无损）：

- **入场**在 f1425 收尾（f1420→f1425 只剩 102 px，f1425→f1430 是 **0 px**）；
- **f1430 .. f1902 连续 473 帧逐像素相同**（0 changed px）——这是真静止，
  不是编码抖动（同一测法在 mp4 上给出 2 600+ px 的假差）；
- **淡出**从 f1903 开始，`non-content` 0.8269 → **1.0000** 单调上升，
  最后落在**背景**上（max RGB 20，不是 0）。

`axisLabel` 当时写着 "LONG-FORM CHART — the entrance has room to be measured"，
而入场 1.33 秒就结束了。**这句话是假的**，改完也必须改。

### 静止长度：不是拍脑袋，是从渲染器自己的 lifecycle 算的

对 `charts/lifecycle.ts` 求"连续多少帧 lifecycle 三个通道（enter / emphasis /
presence）全不变"：

| 场景 | 最长静止帧 | 秒 |
|---|---|---|
| c10 @ 600（改前） | **419** | 6.98 / 10.00 |
| c10 @ 150（改后） | **70** | 1.17 / 2.50 |
| c01_bar @ 150（对照） | **70** | 1.17 / 2.50 |

**改后 c10 与 c01 的静止长度完全相等** —— 这就是"不再是异类"的可测含义。

### 取舍：选 A（保强调），因为前提被推翻了

工单给的三选一建立在"强调会丢"上。实测它不丢（§〇）。所以：

- **选 A**：时长降到 150，**`emphasisIndex: 6` 原样保留**。
  强调曲线在 f69 到达 1.0，之后保持到场景结束 —— 意图完整保留，且**更快到达**。
- **不选 B**（放弃强调）：没有任何东西需要放弃。为了一个被推翻的前提丢掉作者意图，
  是拿真实代价换一个假问题。
- **不选 C**（保留 600 + 加第二段内容）：工单不含这个工作量，需要设计。

| | 前 | 后 |
|---|---|---|
| `c10_bar_long.durationInFrames` | 600 | **150** |
| `c10_bar_long.chart.emphasisIndex` | 6 | **6（未改）** |

这与 P40 记录的"文档里一个过期数字"是同一类缺陷 —— 声明必须跟着它描述的东西走。

## 二、B-2：末帧近黑

### 判据：收尾方式是不是缺陷，取决于它是不是孤例

十个场景全部近黑收尾 —— **零例外**。而且淡出是**平滑**的，不是硬切：

c01 最后 11 帧的相邻帧差：`461354 → 440226 → 446089 → 440263 → 431461 →
428078 → 420556 → 400858 → 383840 → 99078 → 97054`，**每一对都在变**。

### 那条"0.000762 窄门"到底是什么（P23 实测要求先做的）

对 333 帧语料实测 `black_frame` 的读数分布：

| 区间 | 帧数 |
|---|---|
| [0, 0.9) | 23 |
| [0.9, 0.99) | 247 |
| [0.99, 0.999) | 19 |
| [0.999, 0.9995) | 9 |
| **[0.9995, 1.0]** | **23** |

- **所有 FAIL 的帧读数恰好等于 1.000000，23/23，无一例外**；
- 最忙的 PASS 帧是 **0.999367**；
- 所以那个 0.000762 **是两个族群之间的空隙，不是它们重叠的地方**。FAIL 一侧根本没有分布。

> 这一条很重要：**不存在"可调的阈值"**。FAIL 侧是单点 1.0，PASS 侧最高 0.999367，
> 切点已经在空隙正中。移动切点要么不改变判定，要么开始 FAIL 那些**有图形**的帧。

### 工单三条路，我实测的结果

| 方案 | 实测结论 |
|---|---|
| **A 场景末尾豁免** | **采纳**。见下。 |
| **B 连续 N 帧无变化且不在末尾** | **被实测否定**。淡出期间**每一对相邻帧都在变**（上面那串数字）。"无变化"这个判据在真实淡出上恒为假 —— 它读到的是**反面**：淡出是变化，冻结才是相同。这个方案**一个帧都豁免不掉**。 |
| **C 规则不动改 docstring** | 不采纳。B-2 的判定是"误报"，只改说明等于把误报留在那里。 |

### 采纳的 A：豁免是**有位置的**，而且默认关闭

`rule_black_frame(a, frame_in_scene=None, duration_in_frames=None)`：

```
豁免窗口 = 场景声明的 exit 段 = [max(0, dur - max(6, round(dur*0.08))), dur)
```

`EXIT_SHARE = 0.08` / `EXIT_MIN = 6` **不是新数字**，是 `charts/lifecycle.ts`
里同名常量的镜像。守卫 §1 会**真的跑一遍 TypeScript** 并与 Python 镜像逐个比对，
所以镜像漂移会变红 —— 而不是让规则悄悄豁免错的帧。

**为什么必须默认关闭、且必须有位置**：豁免整个黑帧集合，就是造出**第二道永远不红的闸**。
所以：

| 同样的像素 | 判定 |
|---|---|
| 不给位置（旧调用方式） | **FAIL**（行为与 P42 前完全一致） |
| 在声明的 exit 窗口内 | **PASS** |
| **同样像素，但在窗口外** | **FAIL** ← 这条是防豁免过头的 |

豁免的是**判定**，不是**测量**：窗口内的帧仍然报 `noncontent = 1.0`。
一个 exit 帧确实没有内容；变的是"这算不算缺陷"，而当图形被明确要求离场时不算。

## 三、两条判定的张力

工单问：两条改动**是否有冲突**。

**结论：没有冲突，而且它们是同一个问题的两面，处理方式是一致的。**

张力在于：B-2 说"淡出末帧不是缺陷"，B-3 说"8 秒静止是缺陷"。表面上一个豁免、
一个收紧，像是互相拆台。但实测显示：

1. **它们约束的是不同的帧。** B-3 的静止段在 f1430–f1902，
   `non-content = 0.826866` —— **PASS，从来就不是黑帧**。
   B-2 的近黑末帧在 f1928–f1949。B-3 那 8 秒**一行豁免规则都碰不到**。
2. **B-3 的修法让 B-2 的判据更干净。** 静止段被删掉之后，
   c10 与另外九个场景的静止长度完全相等（都是 70 帧）。
   B-2 的判据是"孤例才可能是缺陷"，改完之后**孤例消失了** ——
   十个场景的收尾方式仍然一致，而它们的长度也终于一致了。
3. **反过来，若只做 B-3 不做 B-2 才是危险的**：那会留下"末帧近黑"这条误报，
   而它恰好会掩盖下一个真的末帧问题。

一句话：**B-2 修的是"怎么读"，B-3 修的是"画什么"。前者让后者可以被看见。**

## 四、一个必须记录的副作用：交付的 mp4 已经过期

`pipeline/examples/charts_demo.json` 现在声明 **1500 帧**，
而 `out/charts_demo.mp4`（**只读证据，不属于本线，未重渲**）仍是 **1950 帧**。

这不是小事 —— **P27 的守卫正是从图里推导帧号、再从 mp4 里解码帧的**。
两件事一分开，它会去解**帧 1499**，那是一张**有内容的帧**（实测 0.826298 / PASS），
然后报出一句"82.6% 非内容，PASS" —— **一个描述错误画面的、格式良好的测量**。

这正是 P17 那个缺陷形状，而且是**潜伏在守卫里**的，不是假设。
已修：帧号改从**影片**（ffprobe `-count_frames`）读，并新增一条守卫断言
"影片与图不一致"这个事实本身，让下一次重渲的人撞上它而不是撞上错帧。
