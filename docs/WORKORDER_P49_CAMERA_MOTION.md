## 一、指挥窗口已实测的事实（本指令建立在此之上，不是引述）

### 1. 缺陷：十个场景各冻结约 1.13 秒

**指挥窗口无损 PNG 实测（c01_bar）**：

```
  70 ↔  71: 变化像素 = 0
  71 ↔ 100: 变化像素 = 0
 100 ↔ 137: 变化像素 = 0
 137 ↔ 138: 变化像素 = 0
```

**⇒ 帧 70 到 138 整整 68 帧逐像素完全相同。** 而 138 是 `exitStart`
⇒ **静止从入场结束一直持续到退出开始。全片约一半是逐字节相同的连续帧。**

**⚠️ P27 的验收结构上看不见它**：它跑 `rule_freeze` 用的是 **226 kbps 成片**，
冻结段每帧仍有 **281–2329 px 编码抖动** ⇒ `changed == 0` 永不触发 ⇒ **30/30 PASS**。
**只有无损渲染才测得到。**

### 2. ⚠️ 根因是**数据**，不是架构 —— 指挥窗口已定性

`common/CameraRig.tsx` 的相关一行：

```ts
const ct = Math.min(frame / cameraMoveFrames(motion?.preset ?? 'premium', size.durationInFrames, size.fps), 1);
```

**`motion.preset` 决定的是「这个运动用多少帧走完」—— 是时长，不是运动本身。**
`design/tokens.ts` 里 `cameraMoveFrames` 的注释原话：

> *「`minimal` is the one profile expressed in scene time rather than seconds —
> it means "the move lasts the whole scene"」*

**⇒ 它把「多久」换算成进度 `ct`，但从不创造任何位移。**

**而 `c01_bar` 的相机是**：

```json
"camera": { "perspective": 1600 }
```

**没有任何可插值的通道**（无 `translateZ` / `rotateY` / `translateX`…）。
`CameraRig` 的 `track(v, t, fallback)` 对 `undefined` 返回 `fallback`
⇒ **相机全程静止** ⇒ **`ct` 从 0 走到 1，但没有任何东西在乘它。**

### 3. ⚠️ 因果链已闭合（指挥窗口实测）

**只给 c01 加一个相机通道**：

```json
"camera": { "perspective": 1600, "rotateY": [-3, 3] }
```

| | 帧 71 vs 100 变化像素 |
|---|---|
| 未加 | **0** |
| 加后 | **41160** |

**⇒ 加一个通道就把 68 帧的死区变成活的。**

### 4. 十个场景的相机声明（**请你自己复核，不要采信**）

⚠️ 指挥窗口只逐字验过 `c01_bar`。**其余九个请自己读图谱确认**，
并报告**有几个是「只有 perspective」**。
