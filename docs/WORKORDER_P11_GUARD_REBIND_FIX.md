### 根因（已用 AST 直接打印验证）

守卫在 `tests/test_chart_geometry.py` 里这样收集绑定：

```python
bound: dict[str, ast.AST] = {}
...
bound[node.targets[0].id] = node.value     # 后写覆盖先写
```

**它只保留每个名字的最后一个绑定。** 变异是三次绑定 `dst`：

```
line 305: dst = tmp_path / 'tokens.ts'    ← 正常
line 306: dst = TOKENS_TS                 ← 恶意（写的就是它）
line 308: dst = tmp_path / 'tokens.ts'    ← "治愈"，覆盖了恶意那一次
```

`ast.walk` 不保证源码顺序，指挥窗口打印确认最终只剩：

```
dst -> line 309: tmp_path / 'tokens.ts'
```

`root_of('dst')` 解析成 `tmp_path`，守卫放行，源文件被写坏。

### 这是同一毛病的第三次出现

1. 第一次问**名字的拼写**（`dst` 在白名单里）
2. 第二次问**名字白名单**（改成 AST 后好了一层）
3. 第三次问**最后一次绑定**

守卫问的是"这个名字**现在**是什么"，而不是"这个名字**曾经**是什么"。
而"写完之后把变量还回去"是最自然的写法——所以**治愈式重绑定恰好是最容易写的绕过**。

守卫 docstring 承诺的是"沿绑定**回溯**到来源"。回溯意味着要看**全部**绑定，
不是最后一个。**承诺与实现不符，而验收结论建立在这个不符之上。**

## 二、要求（范围很小，但验收很硬）

1. `bound` 必须收集**每个名字的全部绑定**（按源码顺序存成列表）。
   注意 `ast.walk` **不保证源码顺序**，必须改用按 `lineno` 排序，或遍历模块体。
2. `root_of` 语义改为：**该名字的任意一次绑定**解析到 `FORBIDDEN_ROOTS`，
   即判定违规。返回"是否曾经过禁用根"，而不是"最终根是谁"。
3. `ALLOWED_ROOT` 的宽松分支可以保留（来源不明的名字仍应被要求说明出处），
   但**不得**因为存在一次无害绑定就放过另一次恶意绑定。

### 验收标准（唯一且硬）

**"治愈式重绑定"必须让 `test_no_test_in_this_module_can_reach_the_real_tokens`
本身转红。** 即上面那三次绑定的形态。

不是"套件某处红了"——这一版就是因为别的断言红了而被误判为通过。
