## 一、指挥窗口已实测的事实（本指令建立在此之上，不是引述）

### 1. 缺陷的形状：一把尺子量了两种东西

`studio/scripts/visual_qa.py:119`：`DUP_DISTANCE = 0.5`

`studio/scripts/visual_qa.py:508-522` 的 docstring **原样**：

```
Same measure and SAME threshold as `take_ranker` — mean absolute difference
of a 64x112 grayscale signature, duplicate below 0.5. P1 measured the real take
distribution as {0.000} u [34.5, 67.2], so 0.5 has 34.5x margin to the nearest
genuinely different pair. Reusing the number rather than inventing one is the
point: a second threshold for the same question is a second answer.
```

**问题**：这个 0.5 是**为"两条独立素材"设计的**（选片场景，真实分布 `[34.5, 67.2]`），
而 `--frame-pair` 传进来的是**相邻两帧** —— 相邻帧本来就应该几乎相同。

**P18 实测：20/40 对相邻帧报 DUPLICATE。**

**⇒ 结论**：这不是阈值调松调紧的问题，是**这把尺子量错了对象**。

### 2. ⚠️ 一个待核实的疑点：docstring 说的"复用"可能不成立

指挥窗口实测 `take_ranker.py` 里的 0.5：

```
:106:  return 0.5
:116:  return 0.5
:148:  return 0.5, 0.5
:157:  ..., 0.5, 2, 15, 2, 5, 1.2, 0)      ← 这是 cv2 的参数
:159:  jitter = 0.5
:161:  jitter = float(np.clip(1.0 - (std/mean) * 0.5, 0.0, 1.0))
```

**这些 0.5 看起来是 jitter / 光流参数，不是"重复判定阈值"。**

**请核实**：`take_ranker.py` 里到底有没有一个"重复/相似判定阈值"？
若有，它是不是 0.5？若**没有** —— **那么 `rule_duplicate` 的 docstring 声称的
"同一把尺子"就是一个从未存在的事实**，而这正是本项目最核心的那类失效
（`55b3ac5` 的教训：**docstring 声称的性质必须由代码兑现**）。

### 3. 参考实测数据（P18 测的，请复核）

- 相邻帧对：53956 对，**20/40 报 DUPLICATE**
- 落在阈值两侧的值：**0.498465 / 0.500140**（极其贴近 0.5）

⚠️ **这组数字是相邻帧的分布。若要定一个"帧间变化"的阈值，
它必须由帧序列的实测分布决定，而不是拍脑袋** ——
