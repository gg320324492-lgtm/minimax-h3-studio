## 一、那三个场景到底画没画数值？——**画了**

### 1.1 方法：不靠眼睛，也不靠图谱，靠**对照渲染**

工单第 3 节 (iii) 记着一条血案：「一个声明面能让一个能工作的选项变成惰性」。
所以 `showValues: true` **不算证据**。本项用的证据是：把同一个场景渲染两遍，
只改**一个输入值**，然后看像素。

扰动量的选法是刻意的：

* 改的是 **index 0**，而 index 0 从来不是最大值 ⇒ `fitDomain` 返回同一个 domain，
  `niceTicks` 返回同一组刻度，gutter 宽度不变，**版面不动**；
* 幅度是 1%（c01：48200000 → 48682000；c05：12 → 13；c10：31 → 32），
  打印出来的串**只变一个数字**（`48.2M` → `48.7M`）。

于是标签框里的任何差异，**只能是那个被打印的数字**。
若标签框没有差异，那数字就没被画——无论谁看着像看见了。

### 1.2 实测：标签框像素差异（`out/p45_vlm/control/`）

单位：像素个数（阈值 >40），框 = 被扰动那个值的标签框。

| 场景 | f0 | f20 | f40 | f60 | f96 | f120 |
|---|---|---|---|---|---|---|
| `c01_bar` | 631 | 631 | 631 | 604 | 604 | 604 |
| `c10_bar_long` | 278 | 278 | 258 | 250 | 250 | 250 |
| `c05_bubble` | 1006 | 1006 | 1006 | 1006 | 1006 | 1006 |

**每一个帧的标签框都变了。⇒ 三个场景、全部 18 帧，都有正类。**

c01 与 c10 的差异框被限制在标签盒内，柱体本身没有移动：

```
c01_bar      f 60  changed=604 px  bbox x280-348 y320-341
c10_bar_long f 60  changed=250 px  bbox x240-264 y567-593
```

### 1.3 字形级证据（不识别字也能得出的部分）

标签盒内的连通域**个数与宽度**，A（声明值）与 C（扰动值）对照：

```
c01_bar      "48.2M"  A: 5 个连通域, 宽 13,10,[4x3=句点],12,23
                        C: 5 个连通域, 宽 13,10,[4x3],11,23     ← 只有第 4 个变了
c10_bar_long "31"     A: 2 个连通域, 宽 11, 8                   ← 8px 宽 = "1"
                        C: 2 个连通域, 宽 11,11                   ← 11px 宽 = "2"
```

即：**数值是以字形占据一个文本盒的形式画上去的，而且这个盒的内容跟着底层数值变。**
一个恒定的装饰文字不会随 `48200000 → 48682000` 而改变自己的第 4 个字。

### 1.4 ⚠️ 附带发现：数值标签**不被入场动画门控**

标签盒内峰值亮度，跨整个场景：

```
c01_bar      f0=155  f20=155  f40=155  f60=155  f96=155  f120=155
c10_bar_long f0=154  f20=154  f40=154  f60=154  f96=154  f120=154
```

f0 就已是满亮度并被分类器读成 `48.2M`。源码对应：标签的不透明度是
`f.life.presence`，**没有**乘以每个 mark 的入场进度 `p`（柱体乘了）。

⇒ 对本项的直接影响：**入场早期帧同样有正类**，18 帧全部进入分母。

## 二、`expected_strings` 算得对不对？——**三个都对**

| 场景 | `valueFormat` | `expected_strings` 输出 | 像素是否对得上 |
|---|---|---|---|
| `c01_bar` | `compact` | `['48.2M','39.9M','52.1M','36.8M','61.4M']` | ✅ |
| `c05_bubble` | 字段缺失 ⇒ `auto` | `['12','28','45','66','88','100']` | ✅ |
| `c10_bar_long` | `int` | `['31','48','39','57','44','66','52','71']` | ✅ |

工单点名的两个疑点都不成立：`48200000` 在 `compact` 下确实期望 `48.2M`；
`c05_bubble` 的默认 `auto` 对两位数确实退化成整数 `12`。

**没有发现 `expected_strings` 的 bug。**

### 2.1 但它不是画面上的全部文字

`showAxis` 默认为 `true`，渲染器**另外**画了自己的刻度数字：

| 场景 | 画面上还带着的刻度标签（像素实测） |
|---|---|
| `c01_bar` | `0, 20, 40, 60` |
| `c05_bubble` | `0, 25, 50, 75, 100` |
| `c10_bar_long` | `0, 20, 40, 60, 80` |

`expected_strings` **只问图谱声明的值**，这是它刻意的设计（模块 docstring 写明）。
所以这不算它的 bug——但它意味着：**「画面上没有这个串」不能只看
`expected_strings`**，否则会把刻度数字当成不存在。第五节记录了我因此犯的错。

## 三、准确率

模型 `qwen2.5vl:7b`，`temperature: 0`、`top_k: 1`、`seed: 42`、`num_predict: 8`
（即 `vlm_critic.DEFAULT_OPTIONS`，未改动）。
问题为 P41 的闭合问题：`Does this image contain the text "X" anywhere, exactly as written? Answer with one word, YES or NO.`

**每个探针问两遍**，用于逐字比对可复现性。

### 3.1 主测量（`out/p45_vlm/results.json`，282 次调用）

| 指标 | 分子/分母 | 结果 |
|---|---|---|
| **召回率**（串确实在画面上） | 114 / 114 | **100.0%** |
| **假阳性**（串不在画面上） | 0 / 27 | **0.0%** |
| **可复现性**（两次回答逐字不同） | 0 / 141 | **0 处分歧** |

分场景：

```

c05_bubble   present YES 36/36     absent YES 0/9
c10_bar_long present YES 48/48     absent YES 0/9
```

程序化核对（用画面上真实存在的串做子串判断）：**20/20 正确，0 个假阳性**。

## 五、⚠️ 我犯的错（这一节比数字重要）

### 5.1 阴性对照里混进了坐标轴刻度——**差点记成 VLM 11.1% 假阳性**

第一轮 `absent_for` 用 `v × 1.01` 生成"画面上没有的串"。
c05 的 `45 × 1.01 = 45.45` → 格式化成 **`50`**——而 `50` 正是 c05 的一个 y 轴刻度。

VLM 在三帧上全部、且可复现地回答了 `YES`。

我把像素位图打出来（`out/p45_vlm/frames/c05_bubble/f00060.png`，x115-150 / y625-655）：

```
....+####+....+##+....      ← 左边这个字：上横、左侧竖、中横、右碗、下弧  = "5"
....+++++....+#+.##....
...++.......+#+..+#+..
..+##++.....##....##
..++###+...+##....+#+
.....+##+..+#+....+#+
.......##.+#+....+#+
......+#+.+#+....+#+
......++..##....##
....++...+#+..+#+
..#++.+++....##.+##..
..+###+.......+##+..        ← 右边这个字：闭合椭圆  = "0"
```

**画面上确实印着 `50`。VLM 是对的，我的对照是错的。**

修正：`TICK_LABELS` 按像素测出的刻度标签做排除，然后**整轮重跑**。

> 这一条正是工单第三节警告的：「必须真的看像素，否则无法区分『VLM 读不出』与
> 『本来就没画』」。同一个错误反向又发生了一次——这次错的不是 VLM，是我。

### 5.2 c01_bar 的阴性对照**是空的**

第一版用 `v + 1`，在 `compact` 下是空操作：`48200000 + 1` 仍然格式化成 `48.2M`。
c01_bar 因此**一个阴性对照都没生成**，它的假阳性率会是在空集上算出来的。

### 5.3 整串模板匹配**测出来是坏的，已弃用**

我本来想用它当像素判据。两种度量都测了，都不区分：

```
余弦（二值掩膜）:  真值 48.2M = 0.712      假值 99.9M = 0.735   ← 假值更高
TM_CCOEFF 均值扣除: 真值 48.2M = 0.542      假值 99.9M = 0.585   ← 仍然更高
```

一个对 `99.9M` 给分比对 `48.2M` 更高的匹配器，测出来的召回率没有意义。
**本报告里的任何一个数字都不是用它算的。**

### 5.4 把 `A @ B` 当相关用

两个同形二维数组的 `@` 是矩阵乘法，不是逐元素相关。查下去发现 4×4 的
`arange@arange` 返回 4×4，我一度以为是 numpy 被改坏了——**是我算错了**，
`np.matmul` 和 `@` 行为一致。

### 5.5 像素字形分类器不可靠

它把 `36.8M` 的 `6` 读成 `8`，把 `31` 的 `1` 读成 `T`。
因此它**只作旁证**，不进入任何结论数字。决定性证据是对照差分与位图。

期间还修了两个自身缺陷：句点被 `MIN_H=8` 滤掉（实测是 4×3 px，导致 `48.2M`
被读成 `482M`）；句点几何规则 `max≤6px` 太宽，把 6×6 的**数字**读成句点
（c05 的 `50` 刻度一度读成 `.0.`），收紧到 `≤5`。

## 八、⚠️ 裁定：**这条路开**

理由只用上面的实测数字：

1. **正类存在**，且不是靠图谱自证的：`showValues: true` 被对照差分证实——
   改一个输入值，标签框的像素就变（604 / 250 / 1006 px），18 帧无一例外。
2. **召回 114/114**，假阳性 **0/47**，可复现性 **282 次调用 0 处分歧**。
3. 成本是实测的：冷加载 50.85 s 一次，驻留后 median 0.21 s/次，282 次共 85.7 s。

**P41 记的 0/12 是选错样本**（打在 `c02_line` 上，而它 `showValues: false`，
数值从未被画）。换到真正画数值的三个场景上，同一个判据是 114/114。

### 8.1 开，但带着这四条限制一起开

1. **阴性样本只有 47 个。** 0/47 的 95% 上界约 **6.2%**（rule of three）。
   "0 假阳性"是"在这个样本上没看见"，不是"没有假阳性"。
2. **闭合问题接受子串匹配**（3.3 已实测：`48` 会被算作存在，因为画面上有
   `48.2M`）。问"完整的声明串"时没问题，但它**不是**"这个 token 被印出来了"，
   而是"这段文字出现在画面某处"。这一点应写进 `vlm_critic` 的说明。
3. **18 帧、3 个场景、1 个图谱、1920×1080、1 个模型。** 这不是一个语料库。
   小字、别的分辨率、别的字体都未测。
4. **本项与 `premium` 无关。** 它只证明"VLM 能核对声明的数字确实被画了"。
   一帧画对了所有数字但构图难看，在这里照样 PASS——
   `vlm_critic` 从来就不声称能判好不好看。

### 8.2 给下一个人的一句话

`expected_strings` 单独**不足以**回答"画面上有没有这个串"。
它只覆盖图谱声明的值，**不含坐标轴刻度数字**。
任何阴性对照都必须把刻度排除掉，否则会把自己的错误记成模型的错误——
本项就是这样差点得出 11.1% 的假阳性率。
